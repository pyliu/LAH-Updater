# 功能規格書：維運工具介面圖示相容性

## 1. 問題陳述

LAH-Updater 維運工具的介面與日誌使用 emoji 表示操作和狀態。部分 Windows 系統缺少對應字形，使用者會看到方框，難以辨識按鈕與狀態。工具也必須能在隔離網路中運作。

## 2. 解決方案

將各維運工具介面中作為圖示使用的 emoji 與依賴系統字型的符號，改為離線可用的 SVG。純文字日誌改用清楚的文字標示狀態，讓使用者不依賴圖示也能理解訊息。

## 3. 使用者故事

1. 作為維運人員，我希望按鈕、狀態和功能區的圖示在支援的 Windows 系統上正常顯示，以便辨識操作。
2. 作為離線環境的維運人員，我希望圖示不需要網路或遠端字型，以便在隔離網路中使用工具。
3. 作為使用螢幕閱讀器的人，我希望控制項有明確名稱，以便理解圖示按鈕的用途。
4. 作為檢視日誌的維運人員，我希望文字能說明成功、失敗與警告，以便在無圖示時仍可判讀。

## 4. 實作決策

- 範圍涵蓋 `tools/` 各維運工具的靜態 HTML、JavaScript 動態產生的介面，以及對使用者顯示的提示與日誌。
- 介面圖示採用內嵌 SVG 或隨工具封裝的本機 SVG，禁止依賴 CDN、遠端字型或系統 emoji 字型。沿用簡單、相容目標 WebView 的 SVG 元素，並明確設定尺寸。
- 盤點靜態畫面、動態狀態、彈窗與錯誤提示。以 SVG 取代作為圖示使用的 emoji 與符號，保留文字語意，避免以顏色作為狀態的唯一區別。
- 純文字日誌不得插入 SVG 或 HTML 標籤。以「成功」、「失敗」、「警告」等文字取代裝飾性 emoji；動態介面若呈現日誌，仍須保留可複製、可閱讀的文字。
- 純裝飾 SVG 設為 `aria-hidden="true"`。僅有圖示的控制項必須提供可供輔助技術辨識的名稱；圖示與文字並列時，避免重複宣讀。
- 保留原有功能、操作行為、狀態與版面。圖示需在一般、停用、載入中及深淺色主題等適用狀態保持可辨識。
- 本規格針對工具介面圖示。應用程式的 ICO、PNG 與新工具專屬圖示設計流程維持既有規範，不因介面圖示改用 SVG 而改變。
- 不變更 HTTP API、WebSocket 協定或資料庫結構。

## 5. 測試與驗證決策

- 盤點各工具介面與動態提示的圖示來源，確認範圍內不再以 emoji 或字型符號作為圖示。搜尋結果須人工區分純文字、測試資料與使用者內容。
- 在實際工具或同等 WebView 執行環境中檢查主要畫面、互動狀態、彈窗及錯誤提示，確認圖示可見、尺寸正確且無非預期捲軸。
- 在支援的 Windows Server 2012 R2、2016、2019、2022 與實際部署的 WebView 執行環境中驗證；缺少測試環境時，明確記錄未驗證的版本，不以 SVG 格式本身推定相容。
- 在離線狀態驗證圖示資源可載入。檢查僅有圖示的控制項名稱，以及純文字日誌的可讀性。
- 修改各工具時執行適用的語法檢查，並檢視變更差異。視覺與操作驗證須涵蓋實際受修改的工具。

## 6. 不在範圍內

- 本次規格撰寫不包含實作、重新打包或部署。
- 不修改使用者提供的文字、外部服務回傳內容或既有資料。
- 不重新設計應用程式 ICO、PNG 或改變既有工具的品牌識別。

## 7. 補充備註

現況已在 `tools/backuper/ui/` 與 `tools/dashboard/ui/` 發現靜態及動態 emoji。實作前應擴大盤點至所有工具，並依工具逐一驗證。使用 SVG 可移除 emoji 字型依賴，但仍須實測各部署環境的 WebView。
