# 功能規格書：沙盒 PM2 控制台程序卡片

## 1. 問題陳述

控制台放大字級後，受管業務系統清單的表格高度過小，使用者難以閱讀程序與執行操作。固定表頭也占用有限空間。

## 2. 解決方案

將清單改為依視窗寬度自動排列的程序卡片，讓程序區使用可用空間。維運指南預設收合，程序超出可用空間時在清單內捲動。

## 3. 使用者故事

1. 作為維運人員，我想快速辨識每個程序的名稱與狀態，以便掌握服務健康情形。
2. 作為維運人員，我想在卡片查看 CPU、記憶體、PID、運行時間與重啟次數，以便排查異常。
3. 作為維運人員，我想在卡片啟動、停止、重啟程序與開啟日誌，以便沿用現有操作。
4. 作為維運人員，我想選取程序並查看即時日誌，以便追蹤指定服務。
5. 作為維運人員，我想在不同視窗尺寸使用放大 25% 的文字，以便閱讀而不裁切內容。
6. 作為維運人員，我想按需展開維運指南，以便將空間留給程序清單。
7. 作為鍵盤或輔助技術使用者，我想辨識選取狀態與操作名稱，並能使用鍵盤選取程序。

## 4. 實作決策

- 限定修改 `LAH-Updater/tools/node-portable` 的控制台，維持現有 Tauri 命令、參數及程序資料結構。
- 以自適應卡片取代程序表格，保留各程序原有資訊、空清單及錯誤狀態，並排除日誌輪替模組。
- 使用 Flex 及自適應欄數分配空間，移除造成清單扁平化的固定高度限制。維運指南預設收合，開啟後於可捲動的彈窗查看。
- 使用現有程序選取和日誌行為；重新整理後保留可辨識的選取狀態。操作按鈕不應因點擊而執行其他程序操作。
- 保留控制台字級放大 25% 及離線 SVG 圖示。不可只依賴顏色呈現狀態或選取結果。
- 監控分頁在所有支援寬度使用滿版 Flex。少量程序時，卡片保持自然高度，即時日誌使用剩餘空間；多量程序時僅清單及日誌內容區可捲動。
- 日誌提供展開與收合控制。高度低於 600px 時預設收合，展開後使用精簡控制列；切換回安裝分頁時移除監控專用版面。
- 不變更 HTTP API、WebSocket 或資料庫結構。

## 5. 測試與驗證決策

- 使用隔離的模擬 Tauri 回應驗證空清單、多程序、不同狀態、選取、重新整理及按鈕命令參數，避免操作真實服務。
- 實測預設及最小視窗尺寸，檢查自適應欄數、字級、卡片內容、指南展開，以及清單和日誌的可用空間。
- 執行 JavaScript 語法檢查及 Git 差異檢查。能使用實際 Tauri 環境時驗證互動，無法測試的狀態與環境須明確記錄。

## 6. 不在範圍內

- 不改變 PM2 程序管理或日誌內容的後端行為。
- 不部署、打包正式產物或更動其他維運工具。

## 7. 補充備註

視窗及程序數量會影響可見卡片數。當內容超過可用空間時，清單內可捲動，避免強行壓縮卡片。
