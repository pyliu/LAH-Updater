# MOI-RUST 桌面 UI 規劃草案

日期：2026-11-13。依據使用者提供的五張舊版畫面、SPEC.md 與 LAH_API_SPEC.md。
本文件記錄原始設計提案。現已依使用者指定，以 Tauri 2 實作五分頁桌面展示版；後續服務整合仍待完成。

## 目前實作進度

- 原始碼：`src-tauri/`（Rust 桌面後端）、`ui/`（內嵌前端）。採用五個水平分頁及下方案件明細。
- 執行：`cargo run -p moi-sms-desktop --locked`，或開啟 `dist/moi-sms-desktop.exe`。
- 已完成 Rust 展示資料查詢、篩選、排序、同步去重、展示排程切換、測試輸入驗證與設定檔保存。
- 非密碼設定保存至獨立桌面 JSON；密碼僅保留於程序記憶體，未修改既有 properties。
- 已驗證 Tauri/WebView2 真實視窗與前後端 IPC；查詢、五頁導覽、未儲存切頁提示、設定保存及模擬操作通過。
- 尚無 LAH-API 連線、真實排程／搬移／派送、歷史活動永久保存。展示模式明確標示於畫面。
- 本文件以下內容仍包含尚未移植的規劃，詳細可用功能與建置方式見 `README.md`。

## 目標與假設

- 使用情境：Windows 地政現場人員長時間監看、查詢通知與調整排程。
- 保留五個分頁及熟悉的欄位名稱，改善文字大小、閱讀空間與操作回饋。
- Rust 經 LAH-API 存取資料，設定頁不要求人員輸入資料庫連線帳密。
- 預設開啟「待傳案件」；預設採手動啟動排程（測試期安全），並於系統設定提供「啟動程式時自動開始排程」開關供正式機台無人值守使用。
- 先規劃淺色桌面介面；不以手機或圖表儀表板為第一版目標。
- 畫面可調整大小，設計基準 1200 × 800 邏輯像素；較窄時表格水平捲動，細節改為對話框。
- 驗收需包含現場螢幕解析度、Windows 125%／150% 縮放及繁體中文字型。

```text

排程：執行中｜服務：已連線｜執行時段 08:00–18:30
[暫停排程] [立即同步案件]                              [重新整理]
─────────────────────────────────────────────────────────────────
已登案件    待傳案件    傳送紀錄    傳送訊息    系統設定
─────────────────────────────────────────────────────────────────
查詢日期／日期區間  通知種類  傳送管道  收件字號  [查詢] [清除]

資料表格（固定表頭，可調欄寬、排序、選取、複製）

─────────────────────────────────────────────────────────────────
選取案件詳細資料／完整訊息預覽（可收合）
─────────────────────────────────────────────────────────────────
最後更新 11:57:35｜已載入 200 筆｜下一次掃描 11:58｜目前時間
```

頁籤筆數只有在 API 回傳準確總數時才顯示總數；否則標示「已載入 N 筆」。
同步、派送與查詢各自顯示進度；連線正常不等於排程執行中。
目前圖示與標題顯示的是 SMS 派送管理介面；MOI_EX 的案件同步功能整合為「立即同步案件」。

## 五個分頁

| 頁面 | 主要內容 | 操作 |
|---|---|---|
| 已登案件 | 種類、收件年、收件字、收件號、登錄日期、登錄時間、手機號碼、電子信箱、案件狀態 | 查詢、重新整理、開啟明細；對應 SSMSMAIN |
| 待傳案件 | 種類、收件年、收件字、收件號、待傳日期、待傳時間、手機號碼、電子信箱、傳送種類、已重試次數 | 查詢、開啟明細；對應 SSMSWAIT |
| 傳送紀錄 | 種類、收件年、收件字、收件號、傳送日期、傳送時間、手機號碼、電子信箱、傳送種類、傳送結果 | 日期區間與成功／失敗篩選、開啟明細；對應 SSMSLOG |
| 傳送訊息 | 時間、管道、收件對象、結果、內容摘要；選取後完整呈現內容及錯誤 | 成功／失敗篩選、搜尋、複製、暫停畫面更新 |
| 系統設定 | 服務連線、派送設定、排程、傳送測試 | 儲存設定、取消修改、測試服務連線、發送測試 |

表格日期保留民國格式，如 115/11/13；時刻顯示 11:53:04。頂端目前時間可用西元，均清楚標示。
傳送結果同時使用文字與顏色；欄位截斷時可在明細區完整閱讀，不只依賴滑鼠懸停。
明細顯示複合案件識別資料、收件者、管道、重試次數、完整 subject/msg；未由 API 提供的資訊顯示「未提供」。
不在第一版加入刪除佇列、重送歷史紀錄或批次重送，這些操作目前沒有對應 API 契約。

## 操作與執行狀態

| 狀態 | 畫面與操作 |
|---|---|
| 未啟動 | 顯示「啟動排程」，查詢與設定可用 |
| 執行中 | 顯示「暫停排程」；標示正在掃描、搬移或派送，不允許重複觸發同一工作 |
| 停止中 | 不再領取新工作，完成目前單筆派送及結果回報後才顯示已暫停 |
| 時段外 | 顯示「等待執行時段」與下次時間，不顯示傳送失敗 |
| 連線失敗 | 說明失敗的服務及原因，提供重新連線；保留舊資料並標示最後成功更新時間 |
| 結果回報失敗 | 明確顯示「已送出，結果回報待確認」，不得當成普通派送失敗立即重送 |

「立即同步案件」只觸發案件掃描入列，不承諾立即發送。同步與待傳搬移是不同步驟。
暫停排程不會中斷目前正在進行的外部傳送。
關閉視窗預設退出程式；若有工作執行，提示等待完成並安全結束。縮到系統匣列為後續決策。
查閱傳送紀錄時保留捲動位置、選取列與查詢條件，新資料以提示呈現，不強制跳回第一列。
「暫停畫面更新」僅停止訊息列表自動捲動／刷新，不會暫停排程，兩者文案分開。

## 系統設定布局

1. 服務連線：LAH-API URL、測試連線、站台代碼與名稱（取 metadata，唯讀）。
2. 派送閘道：ap_url、簡訊帳號／密碼、郵件帳號／密碼、寄件地址與寄件者名稱。
3. 排程：搜尋間隔 N 分鐘、最大重試 N 次、開始／結束時間；標示 N 次是否不含首次派送並與服務端一致。
4. 測試：選擇簡訊或郵件、輸入對應收件者、測試主旨／內容、按「發送測試簡訊／郵件」。

設定直接編輯，在頁面內顯示「儲存設定／取消修改」，不使用跨頁共用的確認／取消按鈕。
修改尚未儲存時切頁或離開，提示儲存、捨棄或繼續編輯。
密碼預設遮蔽，可暫時顯示；錯誤訊息與操作紀錄不得輸出帳密。
欄位錯誤就地說明，保存使用者已輸入內容；時間與間隔須驗證合法值。
第一版先採單日開始時間早於結束時間；跨午夜需求另外確認。
測試傳送必須由人員按下明確按鈕才送出，不因儲存或切換收件者自動發送。
舊系統的「密碼修改」需先釐清是應用程式登入密碼或外部帳號；現有 API 沒有驗證及改密碼端點，不先承諾移植。
傳送測試結果獨立顯示，不寫入正式案件佇列或冒充正式案件紀錄。

## 視覺與可用性

- 深藍主操作、白色表格、淺灰頁面，使用輕量分隔線；避免大面積裝飾及動畫。
- 中文使用系統繁體字型（如 Microsoft JhengHei），正文建議 15–16 邏輯像素，表格行高 32–36。
- 成功、待重試、失敗皆有文字標籤；一般文字對比至少 4.5:1。
- 提供清楚的鍵盤焦點、Tab 導覽、表格選取與複製；F5 更新目前頁，Ctrl+S 僅在設定頁儲存。
- 加載中、查無資料、查詢失敗分別呈現。只有成功取得零筆時才顯示「目前沒有待傳案件」。
- 保留手機與 Email 完整閱讀的能力；原型及設計文件使用虛構或遮蔽收件者。

## 與後端契約的關係

| 畫面功能 | API 或資料來源 | 缺口 |
|---|---|---|
| 站台與連線測試 | GET metadata | Rust lah_client 尚未實作 |
| 立即同步 | POST cases/sync | 需顯示新增筆數與錯誤 |
| 排程搬移與派送 | POST queue/enqueue、GET queue/pending、閘道、POST queue/report | 核心流程尚未實作 |
| 三個資料表頁面 | GET records | 目前僅定義 table/limit；須補日期、關鍵字、結果篩選、排序、分頁及回傳欄位 |
| 頁籤總筆數／成功失敗統計 | 需總數或統計欄位 | 不可從 limit=200 的資料推算全體統計 |
| 傳送訊息 | Rust 執行事件及本機紀錄 | 要求歷史查詢時需另外定義儲存、保留期限與載入方式 |
| 設定 | 本機 env.properties | 目前只有讀取，需加入安全寫回、lah_api_url 及驗證 |

GUI 事件與 HTTP 工作分開，網路與檔案操作在背景執行，避免阻塞視窗。
排程控制器與 GUI 分離，未來 CLI 與桌面版共用相同流程。
派送後回報失敗的復原與去重策略必須先定義，再開啟自動派送。

## 建議實作順序與待確認項目

1. 用假資料做五頁畫面及狀態展示，確認欄位密度、明細閱讀與字級。
2. 串接唯讀的 metadata／records，確定 API 欄位、篩選與分頁。
3. 加入設定保存與明確觸發的測試傳送。
4. 實作單次同步、搬移、派送與結果回報，最後加入自動排程。

待使用者確認：是否接受保留五頁的新版布局、現場最低解析度、關窗退出或縮到系統匣、啟動後是否自動開始排程、是否仍需要本機登入與密碼修改。
框架選型留待布局與部署限制確認後進行，不在本提案中預先綁定。
